## What's new

- **Opening the server in a browser goes to the web app.** `https://sloplex.<your-tailnet>.ts.net`, or `http://<nas-address>:<port>` on your network, now opens Sloplex's sign-in page instead of a bare "401 Unauthorized". Apps are unaffected and still get the server root.

## Remote access with Tailscale

These come with the updated `tailscale:` block in the [TrueNAS guide](https://github.com/mtdewwolf/sloplex/blob/v0.3.1/docs/deploy-truenas.md#remote-access-with-tailscale). Replace your block to get them, keeping your own user, key and dataset path. Tailscale stays logged in.

- Plain `http://` addresses, and the short name `sloplex`, now go to `https://sloplex.<your-tailnet>.ts.net`.
- If Tailscale can't use its state dataset, its log now says so and names the user and group to make its owner. Before, it kept retrying without ever logging in.
- The guide now has a troubleshooting table, and says the dataset must be owned by Sloplex's user.

## Other changes

- `strictTokenAuth` is documented, and the request token is read once, by @mtdewwolf in https://github.com/mtdewwolf/sloplex/pull/5
- The TrueNAS guide explains why switching an app back to `latest` can bring back an old release, and says to pull the image first.
- Fixed a test that could fail at random in CI.
