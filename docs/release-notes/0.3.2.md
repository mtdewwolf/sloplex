## What's new

- **Missing media stays in your library until you empty its trash.** A complete scan now marks missing files unavailable instead of removing their catalog records. Restoring a file at the same path and scanning again restores its existing identity and associations. Incomplete or unreadable scans leave the affected library unchanged.
- **Server preferences can be changed through the admin API.** Six settings cover the server name, scheduled scans, folder watching, network discovery and debug logging. Changes are saved across restarts. Server name, scheduled scans and logging apply immediately; folder watching and discovery require a restart.
- **Library and TV identities are more stable.** Libraries can have explicit configuration IDs so renaming them preserves their catalog and references. Editing a show's NFO title or year no longer creates a new show or season identity.

## Before upgrading

Back up your configuration and data directory before upgrading. This release adds stored library identity and availability fields and a `preferences.json` file when preferences are saved. If you need to downgrade, restore your pre-upgrade backup: older versions do not implement these retention and preference rules.

To give an existing library a stable ID, first add a unique `id` to its configuration while keeping its current title and type. Start the server successfully to save that binding, then rename the library while keeping the same ID. Moving media files still does not preserve their identity.

Saved API preferences take precedence over the corresponding configuration-file values. Changing those values in the configuration will not override a saved preference.

## Library trash

Administrators can explicitly purge unavailable catalog entries with `PUT /library/sections/{id}/emptyTrash`. This removes catalog records, not files on disk. There is no automatic trash purge.

Restore files and run a successful scan **before** emptying trash if you want to preserve their existing history. Purged IDs are not reused, and playlist or watch-history records referring to them may no longer resolve. Healthy versions of an item remain playable when another version is unavailable.

## Security and reliability

- Invalid or expired credentials are rejected even on a trusted network. Clients that previously relied on an invalid token falling back to owner access must use valid credentials or intentionally omit the token where tokenless access is allowed. The old `strictTokenAuth` key remains accepted but no longer enables that fallback.
- Tokenless browser access now checks request-origin information. Cross-site requests cannot use trusted-network owner access when that information identifies them as cross-site.
- Revoking tokens, deleting accounts or removing library access stops affected transcode sessions. Unavailable source files are also rejected at playback and delivery checks.
- Stored-file replacement now synchronizes data and, on supported platforms, its parent directory. If replacement succeeds but durability cannot be confirmed, the updated stores retain the installed state and report the error; an error does not always mean the change was rolled back.
- Fixed pagination overflow, partial preference updates from malformed queries, and a transcoder shutdown hang caused by inherited subprocess pipes.

## Compatibility and documentation

Added documented request methods and paths for timeline updates, library refreshes, collection items and subtitle stream URLs. Unsupported options return explicit errors.

The repository now includes independent Claude and Codex reviews, a consolidated findings report, an HTML presentation showing shared findings, and a feature-coverage ledger. These changes do not establish complete Plex compatibility: play queues, per-account language preferences and other recorded features remain pending.
