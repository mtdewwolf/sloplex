# Independent review: requirements for complete Plex Media Server parity

Reviewed commit: `5808f4e5dcfc324714dd5cda1b7064610543b56d`  
Review date: 2026-10-11  
Reviewer: independent GPT-6.1 review agent

## Assessment

Sloplex is a working, deliberately local movie/TV server with a useful web application, local accounts, local metadata, playback state, artwork, collections, video playlists, LAN discovery, and FFmpeg playback. It is not a complete Plex Media Server reimplementation. Most of the Plex settings surface has neither a preference representation nor a compatible API. Music, photos, other-video libraries, Live TV/DVR, downloads jobs, optimized versions, DLNA, and several client-facing protocol families are absent. Existing movie/TV behavior also has identity, authorization, scanning, and durability issues that should be resolved before expanding scope.

The request for **all features and settings** conflicts with the current prohibition on plex.tv integration. A local replacement can implement many server behaviors independently; it cannot claim account claiming, Plex account sharing, cloud resource discovery, Relay, subscription verification, or all official-client behavior while excluding the services those flows use. This is a product scope decision, not an invitation to circumvent subscriptions or fabricate account claims.

This review is a gap inventory and an implementation review, **not exhaustive parity certification**. No particular PMS build, operating system, subscription state, or official-client version matrix is the declared target. Public documentation does not establish every wire detail, default, hidden preference, or platform-specific behavior. A finite, versioned target and lawful observation fixtures are prerequisites for a defensible completeness claim.

### Classification and priority

| Code | Meaning |
|---|---|
| M | Missing: no implemented subsystem or setting behavior found. |
| P | Partial: some behavior exists, but the specified scope is incomplete. |
| U | Implemented but unverified: present, without adequate evidence of PMS parity. |
| D | Intentional divergence: explicitly local/original design; still a parity gap. |
| E | External-service-dependent: requires an account/provider/client/subscription flow outside the current policy. |

P0 blocks the requested definition of the product. P1 blocks a major user flow, access-control boundary, or reliable preservation of user data. P2 covers narrower behavior, operational readiness, and compatibility depth. These priorities concern this requested scope, not a claim that every missing feature must be built before a smaller local product is useful.

## Substantive findings

### F01 — P0 / D, E: the requested scope has no compatible product boundary

**Evidence:** `CONTRIBUTING.md:21-22` rejects all hosted-service calls. `docs/spec/README.md:27-30` keeps identity/accounts/tokens local and permits only specified outbound exceptions. `internal/accounts/accounts.go:39-65` implements local users and device tokens; `internal/server/accounts_api.go:21-36,414-425` exposes local account management and a small compatibility envelope.

**Impact and missing behavior:** claiming a PMS server, account invitations, Plex Home, Plex cloud resource registration, account preferences, watch-state synchronization, Relay, and entitlement-aware official-client flows are not equivalent to local users or a tailnet URL. Plex documents that apps obtain server connection information through [plex.tv resources](https://support.plex.tv/articles/206721658-using-plex-tv-resources-information-to-troubleshoot-app-connections/). Current [remote personal-video playback requirements](https://support.plex.tv/articles/requirements-for-remote-playback-of-personal-media/) also involve account subscriptions. Server ownership, viewer rights, and app/platform requirements must be recorded separately.

**Acceptance:** publish a versioned scope statement that separates (a) locally implementable server behavior, (b) substitute local product features, (c) permitted external providers, and (d) unavailable Plex ecosystem integration. If the goal remains full ecosystem parity, explicitly reconcile the no-plex.tv policy and establish lawful, supported integration boundaries. Never report local identities or fabricated entitlements as verified Plex account compatibility.

### F02 — P1 / M, P, D: no preference registry or compatible settings API

**Evidence:** the complete configuration struct is `internal/config/config.go:25-67`; library configuration contains only title/type/paths at `:17-21`. Startup consumes it once (`cmd/sloplex/main.go:79-106,160-170`). The route registrations in `internal/server/server.go:111-156` contain no server, library, or metadata preferences handlers. The stored section model has no preferences (`internal/library/store.go:38-47`).

**Impact and missing behavior:** a compatible client cannot enumerate typed settings, advanced/hidden flags, allowed choices, defaults, platform/entitlement visibility, persist changes, or observe their effects. Configuration aliases are not a replacement for PMS preference IDs or wire semantics. The official [API reference](https://developer.plex.tv/pms/) documents server preferences, individual preference lookup, section preferences, and item preferences in addition to library management.

**Acceptance:** after fixing the target matrix, create a provenance-backed registry of each preference: ID, type, scope, default, choices, validation, visibility, rights, restart requirement, and actual consumer. Implement and test preference read/write/enumeration behavior and runtime/restart effects. Reject or explicitly identify unsupported values rather than accepting decorative settings. The inventory below is the minimum publicly documented checklist, not an exhaustive hidden-ID list.

### F03 — P1 / M: three major library families are absent

**Evidence:** `internal/config/config.go:70` accepts only `movie` and `show`; `internal/library/store.go:26-34` models only movies, shows, seasons, and episodes; `internal/probe/probe.go:91-109` admits video extensions; `internal/library/scanner.go:234-247` dispatches only movie/TV parsing; `internal/server/items.go:16-26` advertises only those types.

**Impact and missing behavior:** users cannot create a music, photo, or other-video library. Plex documents [five library families](https://support.plex.tv/articles/200264746-quick-start-step-by-step-guides/). Music requires artist/album/track identity, tags and artwork, audio playback/transcoding, disc/track ordering, compilation and album-group behavior, ratings, queues and audio playlists. Photos require image ingestion, orientation/date metadata, albums, browsing and image delivery. Other videos need an independent, non-movie matching model. Merely widening the type allowlist would leave the model and client contracts incomplete.

**Acceptance:** define each family's models, scanner/tag sources, preferences, APIs, playback/artwork, account state, and representative clients. Supply restart/rescan fixtures for multi-disc music, compilations, alternate releases, tagged/untagged audio, mixed photo formats/orientations and missing dates, and personal videos. Separate supported file formats from those PMS itself does not support.

### F04 — P1 / D: editing a library name replaces its identity and drops its catalog

**Evidence:** `internal/library/store.go:271-304` matches sections by type plus display title (`:280,286`), creates a new ID/UUID when the title changes (`:288-291`), and deletes old-section items/collections (`:301-302`). Startup calls this synchronization at `cmd/sloplex/main.go:83-88`. `internal/library/store_test.go:141-155` deliberately expects replacement for changed definitions.

**Impact and missing behavior:** renaming a configured library can invalidate item URLs, playlists, collection membership, account section permissions and watch state keyed by old IDs. This is an existing design choice, not a proven PMS rename rule. The absence of library update APIs compounds it.

**Acceptance:** give configured libraries stable identity independent of display names; support explicit create/update/remove operations and intentional migration of old configurations. A title-only edit must preserve section UUID/ID, item IDs, permissions, collections, playlists and progress across restart. A deliberate removal must have clearly defined, separately tested effects.

### F05 — P1 / P: NFO title/year overrides can churn show and season IDs on every scan

**Evidence:** `internal/library/apply.go:217-237` indexes old shows by their stored display title/year (`:223`), groups the incoming scan by parsed folder title/year (`:232`), then applies NFO metadata (`:236`) while looking up the old show by the earlier parsed key (`:237`). Seasons are reused by the resulting show ID (`:241-242`).

**Impact and missing behavior:** static control-flow analysis indicates that a folder whose `tvshow.nfo` changes its title or year will fail this identity lookup on the following unchanged scan. Show and season IDs can change repeatedly while path-matched episode IDs survive. Container URLs and manual show collection references then become unstable. This is a high-confidence code inference, not an executed reproduction.

**Acceptance:** derive identity from stable scanner/source identity, independently from editable metadata. Repeated scans of a show whose NFO title/year differs from its directory name must preserve all hierarchy IDs; changing the NFO display fields must update metadata without replacement. Add a regression covering collection references and restart.

### F06 — P1 / P, M: incomplete scans are treated as authoritative deletion; no trash retention

**Evidence:** `internal/library/scanner.go:151-159,171-175` skips unreadable nested paths and file-stat failures; scanning proceeds to application (`:113-128`). `internal/library/apply.go:27-50` replaces the prior catalog with the successful observations. Whole-root failures are correctly returned (`scanner.go:152-154`), but nested failures do not receive that protection. Leaf identity is based on matching file paths (`apply.go:77-125`).

**Impact and missing behavior:** a temporarily unreadable subdirectory can remove its catalog entries, and a later recovery creates new identities. File moves can similarly lose associations. There is no retained unavailable-media state or separately controlled trash emptying. PMS explicitly exposes [trash retention and automatic emptying](https://support.plex.tv/articles/200289526-library/).

**Acceptance:** carry completeness/error information through each scanned subtree; never infer absence from an unreadable region. Implement unavailable markers, explicit empty-trash semantics, and a defined move/rematch identity strategy. Fixtures must cover nested permission denial, transient network mounts, interrupted scans, file-stat failures, rename/move, recovery, and toggling automatic emptying without losing progress or playlist references.

### F07 — P1 / P, D: media organization support omits distinct episode/part/edition semantics

**Evidence:** `internal/library/parse_tv.go:13-20,25,89-97` represents one episode per file and takes only the first episode from a multi-episode suffix. `internal/library/apply.go:95-111` makes each scanned file a separate one-part Media record. Movies are grouped by title/year (`:202-209`). `internal/library/parse.go:108-126` hardcodes exclusions and skips extras; `scanner.go:167-169` skips hidden entries and non-regular files.

**Impact and missing behavior:** multi-episode files are not separately represented; split parts behave as alternative versions; editions cannot carry independent state; same-title/year grouping can merge distinct works. There is no `.plexignore` or `.plexmatch` support. Plex documents [TV filename and ordering behavior](https://support.plex.tv/articles/naming-and-organizing-your-tv-show-files/), [movie editions](https://support.plex.tv/articles/multiple-editions/), and [exclusion rules](https://support.plex.tv/articles/201381883-special-keyword-file-folder-exclusion/). Newer [TV editions documentation](https://support.plex.tv/articles/multiple-editions-tv-shows/) demonstrates why older statements that editions are movie-only cannot be treated as a permanent target rule.

**Acceptance:** version the scanner contract, including multi-episode mapping, multipart order, versions versus editions, external IDs and matching hints, episode-order sources, exclusions, and sample handling. Test each with stable IDs and playstate. Do not add unsupported disk-image formats as a purported parity requirement merely because they are absent here.

### F08 — P1 / P, D, E: local NFO metadata is not the PMS metadata-management surface

**Evidence:** `internal/library/nfo.go:21-38` supports a useful subset of local fields. `internal/library/store.go:51-72` has no field locks, edition data or provider identifiers. Metadata emits `sloplex://` GUIDs (`internal/server/items.go:281-305`). Sections advertise `sloplex.local` and hardcoded English (`internal/server/server.go:196-215`). The router has no metadata write/match/unmatch/merge or library agent/language operations (`server.go:111-156`).

**Impact and missing behavior:** users cannot choose agents/languages, correct or lock metadata through client workflows, change artwork, resolve matches, split or merge identities, or use documented collection/rating/extras agent controls. Plex describes current and legacy [agents](https://support.plex.tv/articles/200241558-agents/) and [editable, lockable details](https://support.plex.tv/articles/201272763-edit-details/). Online metadata providers are separately blocked by the current outbound policy; not every metadata operation inherently requires the cloud.

**Acceptance:** specify local metadata edits, field precedence/locks, artwork upload/selection, identity/matching operations, refresh versus scan, and agent capabilities. Preserve changes through refresh/rescan. Treat external enrichment as a policy-dependent provider subsystem, with documented failure/cache behavior and licensing, rather than representing NFO support as equivalent.

### F09 — P1 / M, P, U: official-client orchestration APIs are substantially incomplete

**Evidence:** `internal/server/server.go:111-156` is the complete root route assembly. It has no providers, preferences, play queues, ordinary session status, activities, notifications or general library management. Root capability information is minimal (`:159-172`). `internal/server/playstate.go:100-137` persists timeline progress without an active client/session state model. `internal/server/transcode.go:429-440` lists only transcoder processes.

**Impact and missing behavior:** successful item browsing or the bundled web app does not establish official-client compatibility. Clients may require provider/capability discovery, play queues, session control, events and job progress before or during playback. The [public PMS API](https://developer.plex.tv/pms/) documents these separate families, including `/media/providers`, `/playQueues`, `/status/sessions`, `/activities`, and notification transports.

**Acceptance:** build a client-flow inventory from the target matrix and lawful captures, including startup, discovery, authentication, home/browse, queues, direct play, transcode, timelines, events, errors, and reconnection. Implement only provenance-backed contracts and return accurate capabilities. Test complete flows with real target clients, not just isolated route shapes.

### F10 — P1 / P, D, U: playback decisions use a small original capability language

**Evidence:** `internal/server/decision.go:18-45` uses a few query capabilities and defaults to MP4/H.264/AAC-or-MP3/stereo. Decisions check a restricted codec/channel/size/bitrate/HDR set (`:81-114`) and return original decision codes (`:117-219`). `internal/server/transcode.go:41-168` parses a limited video request. `internal/probe/probe.go:67-82` lacks several codec profile/level, bit-depth and advanced HDR fields. `docs/spec/transcode.md:35-44` labels relevant choices as original design.

**Impact and missing behavior:** an official client's actual profile headers and constraints can be ignored; media that appears decodable by codec name can still fail on level, profile, bit depth, frame rate, container, channel layout, HDR format or subtitle requirements. The API documents profile headers and richer audio/video/location controls, but their exact compatibility semantics still require observations.

**Acceptance:** create a versioned profile/constraint representation backed by public documentation and licensed-client traces. Exercise direct play, remux and conversion decisions on a real client/media matrix, including HEVC/AV1 input, interlaced and high-frame-rate content, multichannel audio, HDR and image/text subtitles. Verify decision fields, selected parts/streams and fallback behavior end to end.

### F11 — P2 / P, M: transcoder knobs and output modes do not cover the published surface

**Evidence:** `internal/config/config.go:25-67,128-129,149-152` exposes a small custom set and requires a positive concurrency limit. `internal/transcode/plan.go:15-40,136-166,206-211` targets H.264/AAC or VP9/Opus, generally stereo, with H.264 hardware encoders. `internal/transcode/throttle.go:19-21` fixes buffer thresholds. `internal/transcode/manager.go:109-149` fixes other operational defaults.

**Impact and missing behavior:** independent hardware enable/encode controls, configurable throttle duration, software quality/background profiles, download temporary storage, disabled video transcoding, remote bandwidth controls, HEVC output/optimization where applicable, and unlimited concurrency semantics are missing or differ. The current [transcoder page](https://support.plex.tv/articles/transcoder/) includes evolving platform, client and subscription conditions; target them explicitly. Existing hardware fallback is useful but is not certification of actual devices.

**Acceptance:** each setting must affect planning or scheduling, expose valid platform choices, and survive restart. Test software and supported GPU paths, device failure/fallback, disable-encoding rejection, temp-space exhaustion, concurrency/unlimited semantics, and configured throttling. Add HEVC output only for the version/client scope that requires it.

### F12 — P1 / P, D: automatic track selection lacks account language preferences

**Evidence:** `internal/server/streams.go:33-67` selects saved overrides, then disposition/default audio or the first track, and the first forced subtitle without language matching. `internal/accounts/accounts.go:39-47` stores no language preferences. `internal/server/streams.go:195-300` implements manual selection and text subtitle delivery/conversion, but there is no subtitle-search/provider API.

**Impact and missing behavior:** multilingual households receive inappropriate audio or forced subtitles, and there are no manual/foreign-language/always subtitle modes, preferred subtitle language, or hearing-impaired/forced search choices. Plex distinguishes [server language settings](https://support.plex.tv/articles/200250357-languages/) from [account track preferences](https://support.plex.tv/articles/204985278-account-audio-subtitle-language-settings/); its automatic-selection behavior is not simply “use the container default flag.”

**Acceptance:** define account-scoped defaults, manual override persistence, language matching and fallback, forced/SDH semantics, subtitle mode, and search capabilities. Test multilingual audio/subtitles, absent preferred language, forced tracks in different languages, explicit none, multipart/version switching and account isolation. External subtitle searching needs a separately permitted provider.

### F13 — P1 / P, D, E: sharing permissions stop at whole-library access

**Evidence:** `internal/accounts/accounts.go:39-56` provides admin status and library-ID visibility only; account updates expose the same model (`internal/server/accounts_api.go:139-151,335-360`). `internal/server/server.go:275-307` allows every visible account to request attachment delivery using `download=1` (`:304-305`).

**Impact and missing behavior:** there are no per-item content-rating/label restrictions, parental presets, per-user download rights, Live TV/DVR rights, managed-user PIN switching, invitations, or account-backed sharing. Plex documents [sharing](https://support.plex.tv/articles/201105738-creating-and-managing-server-shares/) and [restricted access/download permissions](https://support.plex.tv/articles/204232573-restricting-the-shares/). A direct-file attachment is not equivalent to an authorized offline-download job or every documented ownership rule.

**Acceptance:** implement local fine-grained authorization separately from optional Plex account integration. Test restrictions through metadata, search, collections, queues, artwork, parts, subtitle delivery, transcoding, playlists and downloads; no hidden media may leak through counts or child relations. Rights changes must invalidate active delivery, not merely future list queries. Home/PIN behavior needs its own provenance and policy definition.

### F14 — P1 / P: trusted-network owner access combines with unrestricted browser origins

**Evidence:** `internal/server/middleware.go:23-35` permits every origin and preflights mutation methods; its comment assumes header/query tokens make this safe. The same middleware grants the owner principal to unauthenticated trusted-network peers (`:166-168`). `internal/config/config.go:199-208` accepts configured CIDRs.

**Impact and missing behavior:** when unauthenticated trusted-network access is enabled, authorization is ambient to the browser's network position. A page at an unrelated origin may read or mutate owner resources without a token, subject to that browser's mixed-content/private-network restrictions. This is a conditional code-level risk, not a claim that all default installations are exposed or that all browsers permit the request.

**Acceptance:** define origin and CSRF behavior for tokenless trust explicitly. Restrict sensitive cross-origin operations or require explicit credentials for them. Reproduce against the supported browser/network matrix with an attacker-origin page, including preflighted JSON mutations and simple GET mutations; verify allowed clients continue to work. Setting `StrictTokenAuth` alone does not remove tokenless owner access.

### F15 — P1 / D: an invalid/revoked device token can become an owner credential

**Evidence:** `internal/server/middleware.go:160-167` rejects an unresolved supplied token only when `strict` is enabled, then upgrades unresolved trusted-network requests to owner. `StrictTokenAuth` is not default-enabled (`internal/config/config.go:25-92`). `internal/server/strictauth_test.go:9-46` tests the opt-in behavior.

**Impact and missing behavior:** with trusted networks configured and default strictness, a revoked or unknown token obtains owner-level authority instead of failing. This is deliberate legacy behavior in the code, but it undermines device revocation and the expectation of per-user authorization.

**Acceptance:** distinguish absent-token network trust from an explicitly invalid credential, and select a secure, documented default. A revoked user device must never silently become owner. Regression tests should cover revoked, malformed, unknown and absent tokens both inside and outside trusted networks, including public endpoints.

### F16 — P1 / D, P: existing HLS capability URLs outlive user/library revocation

**Evidence:** all HLS session URLs are public capabilities (`internal/server/middleware.go:103-105`). `internal/server/transcode.go:345-381` serves a session by random ID without checking the current account or item visibility. Sessions record account identity (`internal/transcode/manager.go:63-84,350-386`), but `Session` merely touches them (`:458-466`). Account ACL updates/deletion do not cancel them (`internal/server/accounts_api.go:335-380`); stop is scoped to a supplied account/label (`manager.go:479-488`).

**Impact and missing behavior:** a holder of an active session URL can continue fetching media after its account is removed or loses the library. Continued access refreshes the session lifetime. Random IDs reduce discovery risk; they do not implement revocation. Progressive requests also lack the same account/session registration (`internal/server/transcode.go:393-417`; `manager.go:86-94`).

**Acceptance:** define revocable session capabilities, account/item ownership, bounded lifetime, and termination on relevant ACL/token/user changes. Test mid-play revocation for manifests, existing/new segments and subtitle resources; deleted users must not keep streams alive. Track and terminate progressive/direct delivery where the product promises session control.

### F17 — P1 / P, M, E: local HTTP/GDM and a tailnet proxy do not provide network parity

**Evidence:** `cmd/sloplex/main.go:172-207` starts UDP discovery and a plain `ListenAndServe` HTTP server. Config lacks secure-connection modes, certificate inputs, interface selection, Relay, remote-publication and port mapping (`internal/config/config.go:25-67`). `deploy/compose.yaml` publishes TCP service access but not GDM UDP discovery ports. `deploy/compose.tailscale.yaml:36-54` provides a separate userspace HTTPS proxy.

**Impact and missing behavior:** secure connections/certificates, IPv6 and interface behavior, remote status/manual mapping, upload and per-stream caps, DLNA discovery, cloud publication and Relay are distinct capabilities. Plex documents [network settings](https://support.plex.tv/articles/200430283-network/) and [remote access controls](https://support.plex.tv/articles/200289506-remote-access/). A configured unauthenticated network and a network classified as local for bandwidth are also separate concepts.

**Acceptance:** test bare metal and containers, IPv4/IPv6, multiple interfaces, LAN discovery across the chosen deployment mode, TLS and custom certificates, reverse proxies and trusted addresses, NAT/manual mappings and remote bandwidth policy. Identify tailnet access as a substitute deployment option. Cloud publication/Relay remains E until policy and supported integration change.

### F18 — P2 / M, P: analysis, extras and playback-derived metadata are mostly absent

**Evidence:** `internal/probe/probe.go:35-40,67-82` probes streams and color but not chapter/marker/loudness products. `internal/artwork/artwork.go:91-96` generates a poster/art/frame, not preview strips or chapter series. Extras folders are discarded (`internal/library/parse.go:111-126`). The item model has no chapters/markers (`internal/library/store.go:51-72`). Completion uses a fixed ratio (`internal/server/playstate.go:24`) and On Deck uses fixed rules (`:170-239`).

**Impact and missing behavior:** preview/chapter thumbnails, intro/credit/ad markers, voice activity, audio loudness/dialogue analysis, music sonic products, trailers/extras/prerolls, and credits-aware completion are not available. Plex documents [local extras](https://support.plex.tv/articles/local-files-for-trailers-and-extras/), [extras settings](https://support.plex.tv/articles/202920803-extras/), [sonic analysis](https://support.plex.tv/articles/sonic-analysis-music/), and newer [audio enhancements](https://support.plex.tv/articles/audio-track-enhancements-for-video/). Local and online marker sources must be distinguished.

**Acceptance:** introduce versioned analysis products and resumable background jobs with settings, APIs, timestamps, invalidation and cleanup. Validate local chapters/previews/extras and each chosen analyzer on representative fixtures. Do not claim equivalence to an undocumented fingerprint/model solely because a local heuristic finds some boundaries. Newer audio enhancements require the corresponding target server/client/subscription matrix.

### F19 — P1 / M, E: Live TV/DVR is an entire missing subsystem

**Evidence:** library types and item models are video-file-only (`internal/config/config.go:70`; `internal/library/store.go:26-72`); root routes contain no tuner, guide, Live TV, recording or subscription operations (`internal/server/server.go:111-156`). No tuner/recording configuration exists (`config.go:25-67`).

**Impact and missing behavior:** tuner discovery/setup, channel scans/mapping, guide ingestion, live channel tuning and buffering, schedules/conflicts, recordings/post-processing, partial-airing/padding rules, retention and permissions are absent. Plex documents [DVR controls](https://support.plex.tv/articles/225877347-live-tv-dvr/), [XMLTV guides](https://support.plex.tv/articles/using-an-xmltv-guide/) and [subscription distinctions](https://support.plex.tv/articles/226463767-frequently-asked-questions-dvr-live-tv/). A local XMLTV file means not every DVR function inherently requires a hosted guide provider.

**Acceptance:** establish a supported tuner/protocol matrix, local XMLTV parser, guide/channel model, scheduling engine, durable recording jobs, recording playback and permissions. Test real or lawful emulated tuners, restarts, tuner contention, guide changes, missed/partial recordings, padding, storage exhaustion and post-processing. Treat hosted guide access and account entitlements separately.

### F20 — P2 / P, D: collections, playlists and search are narrow custom subsets

**Evidence:** `internal/server/collections.go:17-25,42-85` implements basic admin CRUD, fixed member ordering and a first-member thumbnail. `internal/server/playlists.go:18-54` implements per-account video lists with `Smart=0`; `docs/spec/playlists.md:27-32` expressly chooses private/video-only limits. `internal/server/search.go:15-19,47-120` searches movie/show/episode titles with local ranking. Item filtering/sorting is restricted (`internal/server/items.go:35-65,202-203`).

**Impact and missing behavior:** smart collections/playlists, advanced filter facets, collection visibility modes/custom art/description/order, audio/photo playlists, collection/person/music/photo search, richer recommendations, and queue semantics are absent. Persistent playlists are distinct from [play queues](https://support.plex.tv/articles/202188298-play-queues/); Plex also documents [smart and curated collections](https://support.plex.tv/articles/201273953-collections/).

**Acceptance:** define filter grammar and pagination, permission-preserving dynamic evaluation, editing/order/artwork, supported member types, and queue lifecycle. Test filters changing membership, mixed restrictions, duplicate ordering, client query syntax, search facets, and restart. State which recommendation products are local and which depend on Plex services.

### F21 — P2 / M, P, E: file download is not Downloads or Media Optimizer

**Evidence:** attachment delivery is a query flag on file serving (`internal/server/server.go:304-305`). Transcoding creates short-lived streaming sessions (`internal/transcode/manager.go:128-149,350-386`); there is no durable conversion/download model in `internal/library/store.go:38-113` or job API in `server.go:111-156`.

**Impact and missing behavior:** users cannot manage offline download selection, conversion, progress, quota, per-user rights, client synchronization or durable optimized versions/rules. Plex documents these as [Downloads](https://support.plex.tv/articles/downloads-overview/) and [Media Optimizer](https://support.plex.tv/articles/214079318-media-optimizer-overview/). Client and subscription participation cannot be replaced with an attachment header.

**Acceptance:** separately implement download/conversion jobs and optimized-version provenance, selection, persistence, cleanup, cancellation and storage policy. Test offline clients, resume, permission revocation, original versus converted delivery, optimizer rule updates and version choice. Explicitly classify unsupported client/subscription integration as E.

### F22 — P1 / P, M: atomic JSON replacement lacks a complete durability/backup/migration story

**Evidence:** `internal/atomicfile/atomicfile.go:11-32` writes and renames a temporary file without file/directory synchronization. State mutations precede persistence in `internal/playstate/playstate.go:112-160` and account operations (`internal/accounts/accounts.go:220,291,307,359,406`). Stores are separate (`cmd/sloplex/main.go:79-106`), use fixed version checks (`internal/library/store.go:210-229`; `internal/accounts/accounts.go:99-100`; `internal/playstate/playstate.go:52-63`), and serialize full documents (`library/store.go:491-499`). Account deletion logs secondary cleanup errors yet returns success (`internal/server/accounts_api.go:364-380`).

**Impact and missing behavior:** rename protects against a partially replaced file but does not guarantee power-loss durability. A failed save can leave in-memory state ahead of disk; multi-store operations lack atomicity, rollback and recoverable journaling. No consistent scheduled backup/restore, migration pipeline, corruption recovery or multi-process writer exclusion was found. PMS exposes [maintenance/database export](https://support.plex.tv/articles/226836308-help/) and [scheduled backup restoration](https://support.plex.tv/articles/202485658-restore-a-database-backed-up-via-scheduled-tasks/). PMS's storage format need not be cloned to offer the equivalent user guarantee.

**Acceptance:** define durability guarantees, commit-before-publication/rollback behavior, cross-store transaction/recovery strategy, writer locking, validated versioned migrations and backups of all required state/artwork/configuration. Inject disk-full, permission, rename and write failures; restart after interrupted operations and restore a backup into a clean installation. Successful API replies must correspond to durable or explicitly documented recoverable state.

### F23 — P2 / P, M: scale and operational controls lack evidence and lifecycle limits

**Evidence:** full JSON saves occur per state mutation (`internal/playstate/playstate.go:132-160`); search scans items (`internal/server/search.go:47-64`); filesystem changes trigger full section scans (`internal/library/auto.go:119-143`). Artwork's keyed lock map persists (`internal/artwork/artwork.go:57-66`) and no bounded cache cleanup policy was found. The HTTP server specifies a header timeout only (`cmd/sloplex/main.go:198-207`). Non-Linux filesystem events are unimplemented (`internal/fswatch/fswatch_other.go:1-18`).

**Impact and missing behavior:** large libraries and frequent timelines can incur repeated full-store writes/scans, cache growth, and unproven resource bounds. Long-lived playback needs appropriate streaming timeouts rather than blanket short deadlines, but ordinary admin/read endpoints also need a documented resource policy. “Automatic scanning” on macOS/Windows falls back to polling.

**Acceptance:** publish representative library/concurrency benchmarks and SLOs; bound cache/scratch/job resources, add cleanup/observability and cancellation, and prevent pathological request workloads. Test slow peers, disk exhaustion, many search/timeline clients, filesystem-event storms and large stores. Implement or explicitly exclude native platform watchers in the target matrix.

### F24 — P2 / P: pagination arithmetic can overflow into a request panic

**Evidence:** `internal/server/items.go:177-199` accepts any nonnegative platform-sized integer and computes `start+size` (`:185`); `page` slices using those bounds (`:161-168`). Collection paging uses the same helper (`internal/server/collections.go:97-98`).

**Impact and missing behavior:** with a nonzero start and a size near `MaxInt`, addition overflows to a negative end, producing an invalid slice. This is statically inferred; Go's HTTP server normally recovers a handler panic, so this is a request failure/logging/reliability issue rather than a demonstrated process crash.

**Acceptance:** avoid overflow, bound client page sizes, and return a valid bounded page or an intentional 400 response for unreasonable input. Add boundary/fuzz coverage for query and header forms, zero/negative/oversized values and each consumer; no input should panic.

### F25 — P1 / U, M: passing tests do not establish the requested interoperability matrix

**Evidence:** `.github/workflows/ci.yml:13-29` runs Go checks on Ubuntu, `:31-47` uses Chromium for the bundled UI, and `:59-71` runs container smoke checks. `test/e2e/run.sh:28-46` generates synthetic media and disables discovery in its config (`:81-85`). `internal/transcode/transcode_test.go:65-75` can skip when fixtures/tools are unavailable. `Dockerfile` checks `/identity`, not a media or persistence flow. No lawful PMS-response capture suite or declared PMS/official-client matrix was found.

**Impact and missing behavior:** implementation-consistent tests can all pass while Plex clients fail startup, negotiation or browsing. Synthetic FFmpeg fixtures are useful but do not certify hardware, official clients, TLS/discovery through containers, entitlement handling or all media variants.

**Acceptance:** define exact PMS/platform/client targets and create scrubbed, provenance-backed request/response fixtures plus end-to-end target-client flows. Report integration skips separately; use real GPU runners where claimed, and meaningful readiness checks. Include restart/fault/security tests, Windows/macOS behavior if in scope, and compatibility regressions independent of the bundled web UI.

### F26 — P1 / P, U: provenance is too broad for a complete clean-room compatibility claim

**Evidence:** provenance sections exist, but `docs/spec/http-api.md:5-16`, `docs/spec/discovery.md:5-10`, `docs/spec/transcode.md:5-44`, and `docs/spec/collections.md:5-24` often name generic public/community documentation without exact URLs, versions or capture references. Several choices are explicitly Sloplex design, including playback codes/capabilities and collection/playlists behavior. `docs/spec/README.md:55-56` correctly says such design is not compatibility behavior.

**Impact and missing behavior:** reviewers cannot reliably trace each claimed wire fact to a versioned permitted source, or distinguish a real observation from a convenient imitation. This is a traceability gap, not evidence that prohibited material was used.

**Acceptance:** attach source URL/retrieval date or lawful capture ID, PMS/client versions, platform/entitlement, request setup, sanitized response and confidence to each compatibility fact. Keep original designs labeled; record unresolved behavior rather than guessing. Require spec/evidence changes before implementation, licensed fixture ownership and redaction checks, and a coverage dashboard linking facts to tests.

### F27 — P2 / D: outbound policy wording and deployment expectations disagree

**Evidence:** `CONTRIBUTING.md:21-22` bans any hosted service, while `docs/spec/README.md:27-30` allows GitHub update checks and owner-selected TrueNAS. `cmd/sloplex/main.go:155-157` starts update checks when enabled. `deploy/compose.tailscale.yaml:7,36-54` uses a hosted-network sidecar and a mutable `tailscale:stable` image.

**Impact and missing behavior:** contributors may interpret an already supported flow as forbidden, while users may infer a wholly offline deployment from the absolute wording. The sidecar is separate from application outbound calls, which should be stated precisely. The mutable image also weakens deployment reproducibility relative to the application's pinned base images.

**Acceptance:** reconcile application policy, approved exceptions, optional sidecar behavior and default update checks in one clear statement; document offline operation. Pin or deliberately manage sidecar updates and verify discovery/remote behavior in each supported deployment topology.

## Required parity evidence and remaining uncertainty

A reviewable coverage ledger should link every feature and preference to its allowed source, target version/platform/entitlement, spec paragraph, implementation, fixture and acceptance result. Compatibility claims need at least:

1. Lawful target-client startup, authentication, browse/search, queue, direct/remux/transcode, timeline, subtitles, settings and error traces, scrubbed of credentials and personal data.
2. Media fixtures covering supported container/codec/profile/HDR/channel combinations, multi-episode and multipart files, editions, external IDs, exclusions, local metadata overrides, language tracks, chapters/extras, music tags and photo metadata.
3. Lifecycle/security fixtures for rename/move, partial failure, deletion/trash, permission/token revocation during playback, Home restrictions, origin handling, session expiry and malformed input.
4. Recovery tests for restart, interrupted migrations/jobs, disk full/write failure, consistent backup/restore and concurrent writers, plus scale/resource measurements.
5. Deployment tests for actual LAN discovery, TLS, IPv6/interfaces, NAT and proxies; physical GPU and tuner coverage wherever claimed; separate results per official client and platform.

The inspected code supports a substantial local subset, and its existing checks pass. The absent target matrix, detailed provenance and lawful differential fixtures prevent a reliable claim that even implemented wire behavior is fully PMS-compatible. This report deliberately leaves undocumented defaults, exact private algorithms, unknown settings IDs, and external-service feasibility unresolved rather than inventing parity.
